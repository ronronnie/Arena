# 0003 — Next.js 16, against the prompt pack's pin

- **Status:** Accepted
- **Date:** 2026-08-20
- **Context:** Prompt 0, after connecting Neon Auth
- **Amends:** [0001](./0001-stack-choice.md)

## Context

The prompt pack pins Next.js 15, and Prompt 0 scaffolded 15.5.23. Two things then pushed
against that pin in the same session:

1. **`@neondatabase/auth` declares `next >= 16` as a peer dependency.** Its `./next` and
   `./next/server` adapters — `createNeonAuth`, `auth.handler()`, `auth.middleware()` —
   are the supported path. There was a workaround (the SDK also exposes a
   framework-agnostic `./server` export with a documented `RequestContext` interface we
   could implement in about fifteen lines), but it would have been our adapter to
   maintain against a beta SDK.

2. **Three high-severity npm advisories** — `postcss` ×3 and `sharp`, both transitive
   through Next 15. `npm audit fix` offered exactly one remedy: Next 16.

The deciding factor was timing. At the moment of the decision the app was three files of
placeholder UI, zero components, zero routes that mattered. The upgrade is close to free
now and expensive at Prompt 15.

## Decision

Upgrade to **Next.js 16.3.1** with React 19.2.8 and `eslint-config-next@16`.

## Consequences

**Good**

- `@neondatabase/auth` used as designed, no hand-rolled adapter.
- The three high-severity advisories are gone. Four moderate ones remain, all inside
  `drizzle-kit` (via `@esbuild-kit/esm-loader`) — a dev-only dependency that never ships.
- Turbopack is the default builder; production build of the scaffold runs in ~2s.

**Costs**

- Diverges from the prompt pack's stated stack. Later prompts saying "Next 15" should be
  read as "Next 16"; no prompt in the pack depends on a Next 15-specific API.
- `eslint-config-next@16` ships **native flat config**, so the `FlatCompat` wrapper from
  `@eslint/eslintrc` had to go — it threw `Converting circular structure to JSON` on the
  new config. `eslint.config.mjs` now imports `eslint-config-next/core-web-vitals` and
  `eslint-config-next/typescript` directly, and `@eslint/eslintrc` was removed.
  Both `/lib` boundary guards were re-verified failing after the rewrite.
- Next 16 rewrote `tsconfig.json` on first build: `jsx` → `react-jsx`, and
  `.next/dev/types/**/*.ts` added to `include`. Expected, and left in place.
- A stale `.next` directory referencing the deleted Stack handler route broke `tsc` until
  cleared. Worth knowing if a route is ever deleted again: `rm -rf .next`.

**Revisit if**

- A Next 16 regression blocks a feature prompt. Downgrading would also mean abandoning
  `@neondatabase/auth`'s Next adapter, so the two decisions move together.
